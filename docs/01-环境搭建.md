> 系统自带 3.24.2 会直接 `FATAL_ERROR`。两个解法：

> 2. 传 `-DQT_FORCE_MIN_CMAKE_VERSION_FOR_USING_QT=3.24` 强制跳过（VTK 脚本已兼容，见下）。

### 1.3 关键兼容性约束

1. **CRT 一致性**：MSVC 下 `/MD`(Release) 与 `/MDd`(Debug) 不能混链。三方库仅编译
   **Release**，因此主工程日常开发用 **RelWithDebInfo**（带调试信息但链接 /MD）。
2. **Qt6 + VTK9 OpenGL**：必须在 `QApplication` 构造前调用
   `QSurfaceFormat::setDefaultFormat(QVTKOpenGLNativeWidget::defaultFormat())`。
3. **VTK 模块自动初始化**：链接后必须 `vtk_module_autoinit(TARGETS ... MODULES ${VTK_LIBRARIES})`，
   否则运行时找不到 OpenGL 后端实现。
4. **ITKVtkGlue**：远程模块 + 依赖 VTK 的 Qt 支持，因此 **先 VTK 后 ITK**，且 ITK 配置期
   也要能 `find_package(Qt6)`（需传 `-DQt6_DIR`）。

## 4. 主工程 CMake 组织方式

### 4.1 FindXXX.cmake 包装模式

每个库封装一个独立的 `FindXXX.cmake`（置于顶层 `cmake/`），职责：

1. 解析安装前缀 `<NAME>_ROOT`（默认 `ThirdParty/<NAME>`，可 `-D<NAME>_ROOT=` 或环境变量覆盖）；
2. `find_path` 定位官方 config 文件，找不到时中文报错终止；
3. 透传 `COMPONENTS` 调用官方 `find_package(<NAME> CONFIG ...)`；
4. 导出 `<NAME>_RUNTIME_DIR` 供部署模块拷贝 DLL。

调用侧与官方写法一致：

```cmake
list(APPEND CMAKE_MODULE_PATH "${CMAKE_CURRENT_SOURCE_DIR}/cmake")
find_package(VTK REQUIRED COMPONENTS GUISupportQt RenderingVolumeOpenGL2 ...)
find_package(ITK REQUIRED COMPONENTS ITKCommon ITKVtkGlue ...)
find_package(DCMTK REQUIRED COMPONENTS ofstd dcmdata dcmimgle ...)
```

### 4.2 运行时自动部署（DeployRuntime.cmake）

`deploy_runtime(<target>)` 在 POST_BUILD 阶段：

1. **第三方 DLL**：对 `VTK_RUNTIME_DIR / ITK_RUNTIME_DIR / DCMTK_RUNTIME_DIR`
   三个 bin 目录 `file(GLOB *.dll)`，用 `cmake -E copy_if_different` 拷到 `$<TARGET_FILE_DIR>`；
2. **Qt 依赖**：从 `Qt6::qmake` 路径推导 `windeployqt.exe` 执行
   （`--no-translations --no-system-d3d-compiler --no-opengl-sw`）。

效果：编译后 exe 目录自包含，可直接双击运行。

### 4.3 相对路径约定（不硬编码绝对路径）

项目内所有路径一律用 **相对路径**，外部工具链通过 **环境变量** 定位，CMake 源文件与脚本中
不写死任何 `C:\` / `D:\` 绝对路径：

| 依赖 | 定位方式 | 说明 |
|---|---|---|
| VTK / ITK / DCMTK | `${PROJECT_SOURCE_DIR}/ThirdParty/<NAME>` | 已在 FindXXX.cmake 内相对项目根 |
| Qt6 | **环境变量 `QTDIR`** | CMakeLists 优先读 `$ENV{QTDIR}`，其次 `-DQt6_ROOT=`；未设则报错 |
| MSVC / Ninja | 环境变量 `%ProgramFiles%` | `VS_DIR=%ProgramFiles%\Microsoft Visual Studio\2022\Community` |

> 唯一前置条件：设置一次 `QTDIR` 环境变量（指向 Qt 的 msvc2022_64 目录）。
> 本项目已配置，后续新机器按下面方式设置即可。

### 4.4 配置与构建（脚本化）


## 6. 常见问题（FAQ）

| 问题 | 原因与解决 |
|---|---|
| 配置报 `未指定 Qt6 安装前缀` / 脚本报 `未设置 QTDIR` | 需设置环境变量 `QTDIR`（指向 Qt 的 msvc2022_64 目录）：`setx QTDIR "C:\Qt\6.12.0\msvc2022_64"` 后重开终端 |
| `CMake 3.25 or higher is required to use Qt` | Qt 6.12 要求 CMake ≥3.25。用 `ThirdParty/_tools` 绿色版 3.31.6，或加 `-DQT_FORCE_MIN_CMAKE_VERSION_FOR_USING_QT=3.24` |
| ITK 配置报 `find_package(Qt6)` 失败 | ITKVtkGlue 依赖 VTK 的 Qt 模块，需给 ITK 传 `-DQt6_DIR` |
| 启动黑屏 / 渲染崩溃 | 未在 QApplication 前设置 `QSurfaceFormat::setDefaultFormat(QVTKOpenGLNativeWidget::defaultFormat())` |
| 运行时缺 `vtk*.dll` | POST_BUILD 拷贝被跳过；检查 `ThirdParty/<LIB>/bin`，或重跑 `build_app.bat` |
| Debug 构建链接/运行错误 | 三方库只有 Release(/MD)。**已在 `CMakeLists.txt` 统一处理**：Debug 配置映射到三方库 Release 库(`CMAKE_MAP_IMPORTED_CONFIG_DEBUG=Release`) 且主程序统一 `/MD`(`CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreadedDLL`)，故 Debug 可用(保留 /Od/RTC1/Zi 调试)且 CRT 一致 |
| curl 报 `CRYPT_E_REVOCATION_OFFLINE` | 加 `--ssl-no-revoke` |
| `.bat` 中文乱码 / 找不到命令 | 脚本须存为 **CRLF + UTF-8**（已在仓库内规范化），且从 cmd 而非 MSYS 执行 |
| DCMTK 安全漏洞提示 | 3.7.0 受 2026 CISA 网络服务端漏洞影响；本项目仅本地解析文件不涉及，后续升 3.7.1+ |
